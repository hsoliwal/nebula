## Distilled runtime architecture

The runtime result is deliberately smaller than the donor landscape:

1. **Logical extent is independent of widget/native residency.**
   Virtual Grid rows use sparse logical ownership and materialize stable facades
   only on demand. Million-row viewport tests preserve identity and state across
   distant moves and return to origin.
2. **Painting is viewport bounded.**
   Visible rows plus bounded overscan drive work. Body damage is isolated from
   fixed/frozen and chrome planes.
3. **Z-order is explicit.**
   `GridPaintDAG` orders background -> scrolling body -> fixed/frozen content ->
   header/footer chrome -> transient feedback.
4. **The real SWT `GC` remains the observable/native boundary.**
   `GridGCProxy` is a scoped compiler/proxy, not a replacement graphics API.
   It snapshots and restores mutable GC state, including exact clipping regions,
   affine transform, line/stroke attributes, alpha, antialiasing, interpolation,
   fill rule, XOR mode, colors, patterns and font.
5. **Graphics state is retained only where it pays.**
   `GridGCStateDAG` collapses equivalent stroke and alpha transitions and composes
   ordered affine deltas in primitive float lanes. A renderer boundary flushes one
   native transform transition; identity-cancelling affine batches do not touch the
   native GC. No parallel `StrokeDAG` is introduced.
6. **Headers/scrollbars/editors/feedback are chrome, not row ownership.**
   Vertical body movement does not require semantic header repaint; horizontal
   projection and fixed columns are handled as separate planes.
7. **JFace/viewer logic is model/adaptation logic.**
   Expansion, collapse, selection and viewport mechanics are pushed down toward the
   SWT/runtime owners instead of requiring eager viewer traversal.
8. **Java is semantic authority before JNI.**
   JNI/native promotion requires differential correctness, ownership/lifetime
   proof and a measured crossover. The current Grid GC state DAG remains Java
   because it already coalesces native transitions at the renderer boundary.
9. **Lazy ordered work removes only the demanded top.**
   `GridLazyIntPriorityFrontier` is a primitive max-heap used by sparse virtual
   multi-index removal: O(n) heapify, O(1) top inspection and O(log n) top removal.
   It is not a blanket replacement for primitive sort when the whole input is drained.
