# Bidirectional web widgets and intrinsic SWT/Nebula

There are TWO different directions, not one magic transpiler:
web HTML/JSX/typed template AST -> admitted semantic controls -> SWT Java
and SWT/Nebula Java API -> RAP/RWT browser-client widget deltas.

Reverse translation is limited to structurally inspected, typed source and
must not invent equality for dynamic React hooks, effects, CSS/shadow DOM,
async events, keyboard/focus/IME, selection, accessibility, Unicode, bidi,
resource lifetime and paint geometry. Use existing Synexia TypeScript JSX
and UiBinder AST gates followed by Maven/OpenRewrite Java LST recipes.
Spring MVC/WebFlux and Apache Wicket/Tapestry/MyFaces are server rendering/
HTTP frameworks, NOT Java-to-SWT transpilers. GWT/TeaVM compile Java to
web outputs; Apache Royale compiles ActionScript/MXML to JavaScript.
See WEB_FRAMEWORK_LANES.tsv for each source/output direction and HOLD status.

WEB_SWT_BINDINGS.tsv identifies existing SWT and Nebula classes, the precise
RWT concept and current route, mandatory semantic gates and native allocation
policy. Static form children can each be native Controls. Large data grids,
trees, charts and galleries MUST retain the original SWT/Nebula widget as
viewport, scroll, SetData, selection, GC, damage and lifecycle owner; no
Control per logical row/cell. RAP's Nebula Grid is an existing RWT port;
Canvas paint replay, compound widgets and RAP RemoteObjects are different
techniques and must not be conflated with binary/source parity.

Existing merged Nebula #211 -> #272 retains the static JSX/UIBinder Orders
example and original M3NebulaWebScreen Canvas. This branch ADDS a second,
standalone native-controls example at examples/native-form/src/main/java.
It creates two Labels and two Buttons with the same static text and disabled
Cancel state. It adds no event listener or React reconciliation and is not
wired into the Nebula Tycho reactor. It does not replace the Canvas example.

Current inventories: 66 custom concepts, 68 RWT concepts. RWT-only
VIRTUAL_COMPOSITE and PINNED_COLUMNS are retained in RWT_EXTRA_CONCEPTS.tsv
as explicit candidates, not retroactively counted as implemented desktop
controls. RWT routes in the existing matrix: RAP_NATIVE, CANVAS_GC_REPLAY,
REBUILD_AS_PAINTER, BLOCKED. The read-only Python audit rejects source drift,
undeclared extra concepts, route conflicts, false PASS and one-Control-per-row.
An inventory PASS is NOT a native SWT/RWT execution PASS.

Acceptance: pin source/revision and licensing; invoke canonical Synexia
Maven/OpenRewrite recipe on a reviewed absent/preimage, prove fixed point and
drift refusal; compile exact Java against original SWT/Nebula; execute API,
listener order, selection, SetData, focus/IME, accessibility, clipping, native
resource and pixel tests on Win32/GTK/Cocoa; separately run RAP 4.8.0 session
and browser tests. Until then all mapping rows remain HOLD_UNQUALIFIED.
Canonical templates and tests stay solely in hsoliwal/com.synexia. This
public fork receives only additive result files; no original owner changed.

## JWt and native toolkit execution (2026-10-25)

JWt is Emweb's Java Web Toolkit: widget-oriented Java emits browser HTML/Ajax;
it is not a JSX/DOM-to-SWT transpiler. Upstream offers GPL and commercial
licensing, so this route remains comparison-only; no source is imported.
https://www.webtoolkit.eu/jwt/download

The optional standalone `examples/native-form/pom.xml` compiles the same
existing OrdersNativeForm against actual SWT 3.135.0 (Linux) and, in a
separate profile, RWT 4.8.0. Original SWT native JUnit tests require a real
Display/XVFB and validate child identities, text, enabled state, ownership
and disposal. The RWT gate **only compiles**, not runs a RAP session or web
browser. Neither gate qualifies a general React compiler or all widgets.
All catalogue entries remain HOLD_UNQUALIFIED independently of the small
static form tests.

## Complete 68-concept source projection (2026-10-25)

`WEB_SWT_CONCEPT_MAP.tsv` now binds EVERY current RWT concept ID to its
current SWT stock route, catalogued native Nebula owner (if any), RWT
implementation class, actual RAP/Canvas/rebuild/blocked route, RWT missing
symbol census, and explicit HOLD status. This is separate from the 24
source-shape web bindings; no missing concept is quietly dropped.

`tools/build_web_swt_concept_map.py` is a read-only deterministic projection;
`--check` compares its exact generated bytes to the source-sealed receiver.
The existing `tools/verify_web_swt.py` invokes this parity check in normal
audit mode, so changing either underlying catalogue without regenerating the
full map fails closed. No additional native Controls or widget implementations
are created by this inventory.
