# Browser reentrant evaluate and document-completion ownership — exact original-owner atom

- Product: `hsoliwal/nebula` `master@d56372e7e733bd65bfc3e6f2df0c1327599e315a`.

- Existing behavior: all public/protected Java signatures, ordinary successful trusted document loads, normal install/patch return values, error types, listener ordering and native SWT/RWT Browser ownership are locked.
- Problem: `Browser.evaluate` and Browser progress callbacks can synchronously call application Java listeners which may load a new document or dispose the widget. The original bridge can then mark an obsolete install successful, acknowledge a stale patch, or erase a newer pending document's completion state.
- Repair: use the **existing private** `documentRevision` to refuse stale install/patch acknowledgements, guard `documentRequested` and bridgeFailure writes by the completing source generation, and avoid clearing new document state when an old request returns/throws. Preserve all existing Java types and avoid a second widget, relay or event model.
- Case matrix: normal install; normal patches; stale install with synchronous replacement; stale install with asynchronous replacement; stale text patch with asynchronous replacement; stale value patch with synchronous replacement; disposal during patch; outer failed load returning after a new asynchronous document begins.
- Category: **event-loop reentrancy, versioned state / lease revocation, ABA prevention**. Alternatives: always-clear flags and unchecked Boolean result (baseline broken); a new Browser or event scheduler (rejected: duplicates owners); token revocation in original owner (selected). No LeetCode/HackerRank source is incorporated; classic generation counters and stale-ticket guards are reused as algorithmic patterns.
- Legal: existing first-party code retains its `Apache-2.0 OR EPL-2.0` SPDX; canonical recipe, new proof fixtures and documentation are Apache-2.0. No third-party implementation is imported.
- Qualification: original Java 11 `-Xlint:all -Werror` compile with *test-only SWT API signatures*; baseline bug reproduction; corrected test; unchanged public `javap -public -s` signatures; existing Unicode/lifecycle/Node regression.
