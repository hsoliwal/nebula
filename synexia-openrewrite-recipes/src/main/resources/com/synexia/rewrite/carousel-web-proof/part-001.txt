# Carousel GWT browser source profile

This profile ports the existing Nebula Carousel and ImageContainer owners directly to GWT Canvas2D. Carousel owns one selection and the borrowed caller image list. ImageContainer owns one display Canvas, one temporary two-viewport composition Canvas, and one current Timer. The original SWT sources, public API, native peers and separate RAP integration remain unchanged and unqualified by this browser profile.

The original EPL-2.0 implementation is the source of navigation direction, wrap, synchronous selection notification after slide preparation, programmatic selection without notification, 200ms first/50ms following animation delays, minimum one-pixel progress, and image centering. CarouselGeometry owns the original iterative float32/truncation fit; its GWT Float32 super-source requires Math.fround without a fallback. No generic compiler, inverse UI framework, duplicate selection model, per-image widget or React dependency is introduced.

The browser binding uses ready, positive-natural-size ImageElements. The caller retains its list and resources; dispose never revokes image URLs or destroys caller image elements. SetImages validates every image before changing the owner. The example caller loads the two self-created Apache-2.0 SVG assets first. This browser API is an explicit subset with backend-specific construction and navigation methods; it does not claim SWT binary or full API compatibility.

The browser profile improves lifetime handling locally: a new slide cancels the prior Timer, an epoch rejects stale callbacks, resize/detach cancel animation and release the temporary buffer, and dispose also prevents deferred painting. Hidden or empty navigation commits selection without composing or painting a buffer. Painting intersects requested damage with the window and clipping ancestors. Canvas CSS and coordinate pixels are 1:1; transformed ancestors are outside this first profile and submit no drawing. A viewport is bounded to 4096 per side and 1,048,576 display pixels; the temporary buffer has at most twice that pixel count. Call refresh after changing external ancestor visibility/layout; window resize/scroll and this owner's visibility already request refresh. Detach suspends presentation; reattach refreshes without duplicating data or window listeners.

Compile module `org.eclipse.nebula.widgets.carousel.CarouselExample` with main Java and resource source roots. It emits `carousel/carousel.nocache.js`, which `src/main/webapp/index.html` loads. Compile `org.eclipse.nebula.widgets.carousel.CarouselContractTests` with both main and test Java/resource roots; `contract-tests.html` loads `carouselcontracttests/carouselcontracttests.nocache.js`. Serve the emitted JavaScript and the host/assets from the same HTTP origin. Build commands and paths belong to the bounded qualification runner; this packet does not launch a compiler, server, Node or browser.

`verification/BROWSER_CONTRACT.json` and the browser entry point were authored before the product sources. The browser suite uses real Canvas pixels, local loaded images and real GWT timers, and reports `window.carouselContract` with PASS/FAIL and assertion count. It checks damage, event order, caller identity, overlap cancellation, wrap, hidden/off-window/empty presentation, reveal, refusal and dispose. Geometry has a separate independent reference/corpus and JVM/GWT differential proof input. All new execution remains PENDING until durable actual receipts bind this exact candidate. Recipe execution, numeric tests, browser behavior, native SWT/RAP, Unicode/IME/accessibility, platform/resource/performance and formal review gates are separate; the full Java/JNI/UI goal remains ACTIVE.

`ALGORITHM_EVALUATIONS.tsv` records the chosen donors and required platform category searches. No external problem solution implementation was copied and no performance result is claimed. Java/XML/docs are delivered by the existing hash-pinned snapshot recipes. HTML/SVG use OpenRewrite CreateTextFile with overwriteExisting=false: their tests must prove exact creation, fixed point and existing-file preservation; this does not claim hash-drift refusal for existing assets.
